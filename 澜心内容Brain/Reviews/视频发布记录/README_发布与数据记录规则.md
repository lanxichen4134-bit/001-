# 视频发布与数据记录规则

每一次平台发布对应一条 Publish Record；同一条内容跨平台或同平台再次发布都不改变 Content ID，而是建立新的 Publish ID。

## 文件位置、ID 与链接

第一条真实发布时才建立年份目录，例如：

~~~text
Reviews/视频发布记录/2026/P-C20260824-001-DY-01.md
~~~

Publish ID 格式为 P-{ContentID}-{平台代码}-{序号}。首批平台代码：DY（抖音）、WX（视频号）、XHS（小红书）、BILI（B站）、KS（快手）。记录使用的 variant_id；无变体留空。

post_url 仅在链接公开可用且适合进入公开仓库时填写；否则留空，绝不记录私密后台链接。

## 追加式数据快照

每次收到后台截图或其他可核验的平台数据，都在同一发布记录中新建一个 Data Snapshot，绝不以最新值覆盖旧值。每个快照至少写：

- snapshot_at：数据采集时间。
- hours_after_publish：如可知则填写。
- data_source：平台后台截图、平台可见页面或其他真实来源。
- 平台原始数据：截图/页面实际显示的字段和值；没有的留空，看不清写 [待核]。

平台显示 1.2万等数值时保留原始显示；需要估算时另写 normalized_value 与 approximate: true。AI 计算的衍生指标必须放在 AI计算｜衍生指标 下，写明公式和原始分母，不得冒充平台后台字段。

第一版按平台实际可见情况记录：播放量、曝光量、点赞、评论、收藏、分享、新增粉丝、主页访问、平均观看时长、完播率、留存、私信、咨询、商品点击、进直播间、加企微、进私域、课程咨询、订单、成交金额。没有的字段不虚构。

## 复盘、隐私与 Brain 边界

- 复盘要区分已知事实、可能假设和仍然未知；不能从播放、评论或一条内容推断成交、情绪或普遍规律。
- 用户反馈仅保存去标识化、可公开的摘要：用户在问什么、卡在哪里、对哪句话有反应、高频问题是什么。不得保存用户名、头像、联系方式、订单号、身份信息或不必要的健康细节。
- 新观点只写候选洞见或建议写入 Brain；没有澜心明确确认，不修改 Brain/01、Brain/02、Brain/08 或 Brain/09。
