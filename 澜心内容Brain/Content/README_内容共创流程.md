# Content｜从当前材料开始共创

每一条内容以一个主记录为单位。只有灵感时先讨论；已有观点、稿件或数据时从相应环节开始，明确要求写文案或脚本时直接创作。统一入口见[一句话执行规范](../Docs/ONE_SENTENCE_EXECUTION.md)。

## 默认流程

灵感 → 讨论澄清 → 观点成立 → 三个开头 → 骨架 → 澜心确认 → 成稿 → 发布 → 复盘。

除非澜心明确要求直接成稿，否则不默认跳过讨论。个人故事、学员案例、医学表达和传统文化解释均需标出来源、授权/隐私与证据边界。

## 两条来源路径汇入同一个 Content

- 用户路径：平台评论/讨论 → 显性问题与需求推测 → 选题判断 → 共创/文案/脚本。
- 自身路径：澜心灵感、直播、课程、研究、经历 → 候选观点 → 真实用户场景 → 必要时补研究 → 选题判断/共创/文案/脚本。

两条路径按需交汇，不要求自身观点先完成外部评论研究。研究报告放在现有Content/研究资料的合适主题下（仅保存公开安全部分），候选共用现有选题库；正式内容只保留一个Content ID和正文主位置，原候选卡留索引，不复制全文。研究报告只引用候选与内容位置，不再维护另一套标题库。

## 文案、脚本与平台版本的基础入口

收到直接创作要求，先从已有资料确定一个核心观点、具体女性处境和真实经验/可靠依据，再写可修改草稿及低压力行动或思考。缺少关键主题只问主题；没有真实故事就不用第一人称编造经历。60秒口播按试读校准，不预设固定字数等于准确时长。

按任务选短视频口播、直播式表达、故事、专业知识解释或图示辅助；在同一内容主记录增加“文案/脚本”“拍摄提示（按需）”“平台版本”“修改与复审”小节即可。未启动的形式不填空目录。拍摄提示是建议，不能报告已拍摄/剪辑；详细个人模板以后凭明确反馈补充。

三平台分别写调整理由、稿件及待核条件。共享核心事实，重大开头/结构/时长变化用variant关联，发布后分别建Publish ID。账号、资格或规则缺失可先交标明限制的候选稿，不称可直接发布；内容语义或专业风险要求时允许调整核心表达，不能只改比例字幕。发布前审核版本与实际发布回执分开。

写作风格引用Brain/03、07、09，不在本文件另订长期偏好；四支柱与占比只以Brain/04为准。科学事实、推测、文化解释、个人体验/实践观察分层。旧视频制作SOP只在对应任务获授权且工具实际可用时启用。

## 视频内容档案的接入

正式视频在本流程中仍以一张 Content 内容卡/档案为单位，并使用唯一 Content ID。视频内容档案保存在 [视频档案](视频档案/README_视频档案规则.md)，逐字稿保存在 [逐字稿](逐字稿/README_逐字稿规则.md)；媒体制作进度填写 media_stage，不改变现有 status 状态链。

视频的原始媒体、后台截图和本机绝对路径不进入公开 GitHub。完整规则见 [视频内容档案系统](../Docs/VIDEO_CONTENT_SYSTEM.md)。
