# 只需准备一次，以后直接说任务

本轮已准备好文件；目标ChatGPT Project和Work会话尚未实际配置、上传或读回。资料不会因为GitHub更新就自动进入另一个账号。本说明不要求创建第二套长期事实库，可复用已有项目。

## 一次性操作

1. 打开你要长期使用的ChatGPT项目。核对账号及共享范围，只放公开安全的阅读资料。
2. 将本文件夹中的01—06，以及08这七份Markdown上传到该项目的资料/来源区域。02—05是沿用的个人事实快照，01、06、08是本轮更新；不要上传原始聊天、评论截图或健康资料。
3. 打开[07复制版](07_Project_Instructions_复制版.md)，仅复制“阅读正文从下一行开始”之后的正文，放入项目Instructions/项目说明，不复制前面的来源元数据。
4. 在这个项目内开始Chat或Work任务。第一次使用Work时，把[Work执行入口](../Prompts/09_Work执行入口.md)正文作为开场说明；08已包含同一正文及研究规则，不用另建知识库。
5. 发送：“请先告诉我你实际读到了哪些资料版本，说明一句话执行、原话保护和三层报告怎样工作；没有收到的资料直接告诉我。”收到真实读回后才记为配置完成。暂时没有项目设置入口时，可在单次任务附必要文件和入口正文，仍不称项目配置完成。

日常只需说：“帮我看看这个话题值不值得讲”“把这段直播整理成三个选题”“直接写一条60秒口播稿，主题是……”。无需记编号或填写技术表。

本轮小红书专项更新复用原08，正式规则为V2.1；已上传过旧版时替换受影响的06、07、08并读回版本，不新建第二套Brain。执行评论研究时，还需让Work实际收到[模板说明](../Docs/XIAOHONGSHU_RESEARCH_TEMPLATES_V2.1.md)所链接的04矩阵和05 V2.1-r1空白模板；08内含说明文字，不能代替Excel文件。实际填充副本放在获准受控位置，不回传公开GitHub。本次没有替用户完成线上上传、配置或浏览测试。

## 给另一个账号或工具时

只交本次需要且允许转交的资料、Work入口与AI生成的任务交接说明。不要假设对方拥有当前聊天、文件夹、GitHub或小红书登录。让接收方报告实际可读资料、版本、工具及缺口。若需要登录或验证码，由你在正常界面完成，不把凭据发给AI。

正式评论研究前仍需最小能力测试与独立会话复验；文件上传成功不是浏览测试成功。没有自动发送能力时，AI只会交给你可复制说明，不声称已经把任务送出。

## 以后怎么更新

先在正式Brain、Content、Reviews、Docs或Prompts修改，Codex按仓库规则提交推送并验证，再用新版阅读文件替换目标Project中的旧文件，更新07指令并读回。不要在Project副本独立维护新事实；新确认反馈交Codex回写原有主文件。

01、06、07、08由[框架工具](../Docs/framework_tools.py)从正式源生成，内含源路径与内容SHA256，不能手工改副本。02—05沿用既有紧凑摘要，本轮Brain未变；未来Brain变更时需由Codex复核/再生成相应摘要。完整工具步骤供Codex使用，澜心无需操作命令：

```sh
python3 澜心内容Brain/Docs/framework_tools.py sync
python3 澜心内容Brain/Docs/framework_tools.py check
```

此工具的保护基线属于2026-10-21专项升级验收，未来经授权修改Brain时应同步更新检查基线和验收依据，不能为了让检查通过而撤销正确内容。模板审查仅检查已审空白文件，不是对实际研究资料的公开许可。

生成副本中的链接用于回查GitHub正式源，当前阅读内容以随附来源摘要值为准；链接指向main最新文件，可能比已上传副本更新，发现差异应重新同步，不混用版本。只在得到上传及读回证据后报告“目标环境已同步”。
