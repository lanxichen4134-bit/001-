# 直接说你现在想完成什么

澜心内容Brain保存真实灵感、已确认的长期知识和可追溯的内容资产。你不用填写任务表，也不用从头重走流程；说清眼前想做的事，AI先读取已有资料，再选择合适入口。

## 可以这样开始

- “帮我把这句话保存成灵感。”原话保留，AI理解另放，不自动变成长期观点。
- “帮我看看这个话题值不值得讲。”给结论、依据、其他解释与风险。
- “把这段直播整理成三个短视频选题。”只根据实际提供的素材提炼，证据不足不凑题。
- “按我的风格写一条60秒口播稿，主题是……”直接给可修改草稿。
- “这个文案不像我，保留观点，把开头改自然一点。”针对现稿修改。
- “把这条内容做成三个平台版本。”分别说明修改理由和待核条件。
- “复盘这条视频，数据在这里。”用真实数据比较，保留历史快照。
- “这条表达要求以后都采用，保存为长期规则。”确认范围清楚且公开安全就更新原有Brain。

## 谁负责什么

Chat是主要入口，负责理解、讨论、统筹、共创与复核；Work负责实际研究和多步骤任务；Codex负责知识库、规则、文件与GitHub版本。能直接完成就做，需切换时AI准备交接说明。三个环境的资料、登录与权限必须实际确认，不能因文件建好就宣称全部联通。

[一句话执行规范](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Docs/ONE_SENTENCE_EXECUTION.md)是统一规则；[Work中文入口](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Prompts/09_Work%E6%89%A7%E8%A1%8C%E5%85%A5%E5%8F%A3.md)可直接交给执行端；[三层报告标准](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Docs/RESEARCH_REPORT_STANDARD.md)让推荐理由与证据可查。

## 内容从哪里来

用户研究可以从小红书的真实问题进入；澜心自己的灵感、直播、课程、研究与经历同样可以进入。两条路径使用同一个[Content内容入口](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Content/README_%E5%86%85%E5%AE%B9%E5%85%B1%E5%88%9B%E6%B5%81%E7%A8%8B.md)。已有稿件直接改，已有数据直接[复盘](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Reviews/README_%E5%86%85%E5%AE%B9%E5%A4%8D%E7%9B%98%E6%B5%81%E7%A8%8B.md)。原始表达遵守[Inbox保护规则](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Inbox/README_Inbox%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E.md)。

内容状态仍为：raw_idea → discussing → idea_clear → structure_ready → drafting → approved → published → reviewed。内容的研究、制作、发布条件各自检查，草稿完成不意味着可以自动发布。
