# 一个入口，两条来源，一套内容资产

澜心用自然语言向Chat提出任务。Chat统筹理解、共创和复核；Work承担已授权的研究及多步骤执行；Codex维护文件与版本。这是工作分工，工具可用性和跨环境交接每次实际确认。规则见[一句话执行规范](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Docs/ONE_SENTENCE_EXECUTION.md)。

~~~mermaid
flowchart TD
  A[澜心一句话] --> B[Chat理解任务与已有材料]
  B --> U[用户路径：授权研究与可核查评论]
  B --> P[自身路径：灵感 / 直播 / 课程 / 研究 / 经历]
  P --> I[Inbox原话或既有素材索引]
  U --> R[三层报告：结论 / 完整理由 / 证据]
  I --> C[共用Content：观点 / 选题 / 共创]
  R --> C
  B --> M[已有稿件修改或实际数据复盘]
  C --> W[按需文案 / 脚本 / 逐平台适配]
  M --> W
  W --> H[事实与专业审校 / 澜心确认]
  H --> F[另核授权和条件后实际发布]
  F --> V[Reviews：Publish记录与追加数据快照]
  M --> V
  V --> K[候选洞见与规则建议]
  K --> Q[澜心明确确认范围]
  Q --> L[原有Brain唯一主位置]
  L --> S[正式源生成Project与Work阅读快照]
~~~

箭头说明可衔接的环节，不要求每次走全程。已确认观点可直接写稿；现稿可直接修改；已有数据可直接复盘。外部研究不是个人表达的必经前置条件。没有评论证据不能伪装成已研究。

## 主位置与边界

| 模块 | 唯一职责与主位置 | 不自动发生的动作 |
|---|---|---|
| Brain | 已确认个人定位、价值、表达、方向、故事、观点与红线 | 候选和临时反馈不自动升级 |
| Inbox | 原始灵感及独立AI理解，处理后追加去向链接 | 不覆盖或删除原话 |
| Content | 共用选题库、共创记录、研究资料、内容档案与脚本；一份正文一个主位置 | 不因来源/平台/工具不同复制内容库 |
| Reviews | 每次实际发布的记录、追加Snapshot、复盘和下次实验 | 不覆盖历史值、不把相关当因果 |
| Docs | 系统规则、状态、决策、来源与资产索引 | 不承载原始敏感研究正文 |
| Prompts | Chat、Work、Codex的可直接使用入口 | 指令不等于权限、能力或实际执行 |
| Project资料同步包 | 从正式源生成的阅读快照和操作说明 | 不作为独立事实库，不代表已上传 |

内容状态唯一链为：raw_idea → discussing → idea_clear → structure_ready → drafting → approved → published → reviewed。阶段可按任务直接进入，但状态须反映实际成熟度，跳过讨论不等于自动approved。

研究层级S1—S6是证据评估字段；media_stage是媒体进度；二者不写入Content status。正式内容沿用一个Content ID，同题跨平台只关联variant和各次Publish ID。详见[视频系统](https://github.com/lanxichen4134-bit/001-/blob/main/%E6%BE%9C%E5%BF%83%E5%86%85%E5%AE%B9Brain/Docs/VIDEO_CONTENT_SYSTEM.md)。
