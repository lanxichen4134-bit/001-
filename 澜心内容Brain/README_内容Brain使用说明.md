# 澜心内容 Brain 使用说明

这不是“让 AI 批量生产内容”的资料夹，而是澜心自己的长期内容操作系统：灵感不丢失、原话有保护、观点有来源、内容先共创、研究有边界、每次执行能在 GitHub 留下可验证记录。

## 从哪里开始

1. 突发灵感或原始转写：先看 [Inbox](Inbox/README_Inbox使用说明.md)，保存原话，不急着写成文章。
2. 想把一个想法讲清楚：使用 [内容共创 Prompt](Prompts/03_内容共创_首条Prompt.md)。
3. 已确认要成稿：在 Content 建立一张内容卡；一条内容只讲一个核心观点。
4. 发布后：按 [复盘流程](Reviews/README_内容复盘流程.md) 记录可见数据、感受、反馈和下一次唯一变量。
5. 新建 ChatGPT Project：打开 [项目资料同步包](Project资料同步包/00_上传与使用说明.md)。

## 事实源与同步关系

~~~text
澜心明确输入 / 已确认 Brain
        ↓
内容共创与内容卡
        ↓
发布与复盘
        ↓
需要时由 Codex 重新生成 Project资料同步包
~~~

Brain 是本仓库内的长期事实层；同步包只是上传给 ChatGPT Project 的阅读快照，不能在两处各自维护一套真相。

## 本仓库与旧资产的关系

本仓库的 Docs/EXISTING_ASSET_MAP.md 记录已有 Obsidian Vault 中的素材入口。旧 Vault 的正文、研究、课程、原始资料继续保留原位置；本 Brain 只做必要的引用、索引和去标识化结论，避免形成重复数据库。

## 内容状态

~~~text
raw_idea → discussing → idea_clear → structure_ready → drafting
→ approved → published → reviewed
~~~

不要另建第二套状态词。内容状态表示内容成熟度，不表示一个人或观点的价值。
