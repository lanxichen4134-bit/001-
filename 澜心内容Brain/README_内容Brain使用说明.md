# 直接说你现在想完成什么

澜心内容Brain保存真实灵感、已确认的长期知识和可追溯的内容资产。你不用填写任务表，也不用从头重走流程；说清眼前想做的事，AI先读取已有资料，再选择合适入口。

## 可以这样开始

- “帮我把这句话保存成灵感。”原话保留，AI理解另放，不自动变成长期观点。
- “帮我看看这个话题值不值得讲。”给结论、依据、其他解释与风险。
- “把这段直播整理成三个短视频选题。”只根据实际提供的素材提炼，证据不足不凑题。
- “按我的风格写一条60秒口播稿，主题是……”直接给可修改草稿。
- “这个文案不像我，保留观点，把开头改自然一点。”针对现稿修改。
- “把这条内容做成三个平台版本。”分别说明修改理由和待核条件。
- “复盘这条视频，数据在这里。”用真实数据比较，保留历史快照。
- “这条表达要求以后都采用，保存为长期规则。”确认范围清楚且公开安全就更新原有Brain。

## 谁负责什么

Chat是主要入口，负责理解、讨论、统筹、共创与复核；Work负责实际研究和多步骤任务；Codex负责知识库、规则、文件与GitHub版本。能直接完成就做，需切换时AI准备交接说明。三个环境的资料、登录与权限必须实际确认，不能因文件建好就宣称全部联通。

[一句话执行规范](Docs/ONE_SENTENCE_EXECUTION.md)是统一规则；[Work中文入口](Prompts/09_Work执行入口.md)可直接交给执行端；[三层报告标准](Docs/RESEARCH_REPORT_STANDARD.md)让推荐理由与证据可查。

## 内容从哪里来

用户研究可以从小红书的真实问题进入；澜心自己的灵感、直播、课程、研究与经历同样可以进入。两条路径使用同一个[Content内容入口](Content/README_内容共创流程.md)。已有稿件直接改，已有数据直接[复盘](Reviews/README_内容复盘流程.md)。原始表达遵守[Inbox保护规则](Inbox/README_Inbox使用说明.md)。

内容状态仍为：raw_idea → discussing → idea_clear → structure_ready → drafting → approved → published → reviewed。内容的研究、制作、发布条件各自检查，草稿完成不意味着可以自动发布。

## 正式知识与阅读副本

GitHub origin/main是唯一正式版本源，Brain是长期个人事实的主位置。旧Obsidian为只读辅助资料；不在两处维护同一正文。Project/Work使用[同步包与一次性操作说明](Project资料同步包/00_上传与使用说明.md)，更新正式源后重新生成，不手工维护第二套事实。

本次升级已建立规则、入口与本地检查；平台研究、跨会话浏览、Project界面配置及真实发布仍需各自验证。详见[本次验收记录](Docs/FRAMEWORK_ACCEPTANCE_2026-10-19.md)。

仓库为公开：不提交凭据、敏感健康信息、私密聊天、原始音视频和未公开经营资料。保存授权与公开安全分别检查；候选观点和AI建议不自动升级Brain。
