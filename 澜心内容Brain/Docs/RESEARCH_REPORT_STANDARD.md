# 让澜心看懂每一项推荐

Chat、Work、Codex 共用本标准。报告先回答“推荐什么、为什么”，再让证据可查。完整底层逻辑指可解释的事实依据、分析、取舍和边界，不要求展示模型内部隐性推理。只有标题、评分、流程箭头或填满字段，不算完成研究报告。

本文件兼作空白模板，避免另维护一份报告规则。具体研究方法、能力验证与五门槛以[研究参考](XIAOHONGSHU_TOPIC_RESEARCH_REFERENCE_V1.0.md)为主；内容继续进入现有 Content，不另设选题库。研究任务止于其授权范围；明确要求写稿时可以另接创作，本模板不构成永远禁止写作的限制。

## 第一层：给澜心看的结论

用几段清晰中文说明本轮研究的人群、场景、问题与目的，实际看到了多少笔记及合格评论，得到什么发现，推荐什么、暂缓什么、为什么，以及现在最需要澜心决定什么。数量未统计就写未统计，没有合格候选就写0。区分已观察到的表达、候选机会、具备制作条件的题目与已人工通过的版本。

开头不放几十列技术表。必要时用“候选、建议、理由、主要缺口”四列短表帮助比较，不能用它代替下文。明确本轮停止位置、没有做的环节和结果限制；选题认可不等于已拍摄、平台批准或效果得到验证。

## 第二层：完整底层判断逻辑

先写研究整体判断，再为每个推荐写独立可读的论证。以下十个问题均须回答，不适用时说明理由：

1. 为什么研究：对应哪项最新要求、已确认人群/目标和真实场景；不替澜心默认销售目标。
2. 为什么这样取样：关键词连接什么场景，为什么选这些图文/视频笔记，排除了什么，热门与排序带来什么偏差。
3. 实际表达是什么：以必要且允许展示的短摘录或明确标为概述的文字，关联证据索引；未看到的评论不补写。
4. 如何识别问题：哪部分直接支持“谁在什么场景遇到什么障碍”，身份或年龄不知道就不推定。
5. 事实、分析与推测如何分开：显性问题有直接依据；潜在需求只是推测；其他解释及反例是什么。
6. 为什么与澜心有关：关联具体 Brain 内容方向、真实知识/经验或专业资源；资质、审核人和实际回答范围是否成立。
7. 为什么选这个原创视频角度：只解释什么核心问题、对观众有什么理解价值；为什么选择这种形式，人员和素材能否落实。
8. 为什么排除其他角度：比较实际备选或明确标为“策划对照”的 AI 替代方案；不编造另一个用户需求或假装做过对照试验。
9. 三个平台各自怎样判断：抖音、小红书、微信视频号分别说明账号、人群、表达、专业、商业和规则依据；未知不写成不适合或已合规。
10. 限制与下一步：样本不能支持什么，什么新证据会推翻本次判断，谁需要确认什么，用什么最小后续动作验证。

每个重要判断都写清六件事：依据是什么、支持到哪里、哪些是推测、替代解释是什么、仍然未知什么、什么情况会推翻判断。可以合并成自然段，不要求机械使用六个小标题。与资料存在冲突时指出冲突，不以流畅文案掩盖断点。

### 每题可直接使用的正文框架

“这条题目回应的是____场景中的____问题。实际依据来自____，其中直接表达的是____；我们推测____，但也可能是____。这与澜心已确认的____方向有关，能够回应的依据是____，不能回答的范围是____。因此建议用____原创角度讲清____，预计帮助观众理解____；这一观看价值仍需验证。与____策划对照相比，选择本题是因为____。目前人员、素材、授权与专业审核____，因此只能推进到____。抖音建议____、小红书建议____、视频号建议____，各自依据与缺口为____。若后续出现____证据，本次推荐应调整或撤回。现在只需澜心决定____。”

空格由实际证据填写，不为填满模板编造。资料不足时明确缩小结论。个人素材路径没有外部评论时，引用实际直播段落、课程或灵感原文，写“用户需求尚未外部验证”，不捏造评论链。

### 选题与平台判断随正文附上

- 五门槛：来源可核查、受众及方向相关、可靠回答能力、清晰可制作的原创角度、专业伦理与合规边界。分别写通过／待补证／不通过及依据，总分不得抵消风险。
- 研究层级：S1真实表达、S2有效问题、S3潜在机会、S4适合澜心方向、S5可制作核心选题、S6人工研究审核。它们仅用于外部研究证据评估，不是 Content status。没有评论来源的个人素材不得被伪装成S1用户评论；该维度注明不适用并查自身来源。
- S5要求研究范围内五门槛通过、必要人员素材有据；S6须指定业务及必要专业审核人对具体版本确认。缺项降级或暂缓。平台发布条件单列，若缺口影响核心回答能力则不能拆分放行。
- 可制作性说明：观众为什么看、单一回答范围、澜心凭什么讲、原创形式及理由、人员素材及授权、风险及停止条件。

| 平台 | 本轮初评 | 依据与账号/规则版本 | 缺口及解除条件 |
|---|---|---|---|
| 抖音 | 待填写 | 待核 | 待核 |
| 小红书 | 待填写 | 待核 | 待核 |
| 微信视频号 | 待填写 | 待核 | 待核 |

初评只使用：适合继续开发／需要调整内容角度／需要补充审核或资料／暂不适合该平台／对应平台规则尚未核实。若有多项缺口，主状态加正文分开说明。每平台核账号定位与人群、核心表达、标题封面、身体画面/音频/字幕、医疗两性内容、认证、广告/导流、版权、AI标识及必要人审。每项均按实际材料判断，不预设三平台画像、通发方式或最佳时长。只有部分平台条件成立时，只推荐相应范围；“适合继续开发”不是发布许可。

## 第三层：证据与工作记录

以下字段由执行方记录，澜心日常不用填写。只保留任务必需的记录；这些字段以可读小节或窄表展开，不创建一个几十列的总表。

### 批次和授权

- 原始要求、目标、范围、日期与时区、资料截止时间、输入版本。
- 已确认人群/方向/目标所引用的 Brain 路径和条目；业务能力、出镜、专业审核人、账号、认证、发布次序等未知项。
- 实际执行环境、可用工具、授权范围、计划与实际时间/数量、人工介入和局限。
- 任务是能力验证、复验、研究小样、补证、复审还是个人素材分析；不混称完成。

### 来源与证据索引

编号仅供内部查证，不要求澜心记忆。一轮RUN共用稳定编号：BID=批次、QID=检索、AID=账号、NID=笔记、OID=每次观察、CID=归并后的评论、PID=问题、TID=候选、EID=证据、LID=问题评论关系。CID跨B2/B3不重编；跨轮引用写全RUN/类型/编号。LID不是可定位评论指标L，CID不是正式Content ID，PID不是Publish ID；旧视频SOP的Q原话/P个人证据也须加语境区分。具体字段与容量见[模板说明](XIAOHONGSHU_RESEARCH_TEMPLATES_V2.1.md)。

| 记录 | 必须可查的内容 |
|---|---|
| Q检索 | 精确关键词及词类、选择理由、时间时区、入口、实际排序/筛选、观察范围、扩词或停止原因、E关联 |
| N笔记 | 图文/视频类型、来源定位、发布及观察时间、可见互动原值、实际阅读页次/视频范围、账号资质显示及未核处、选入/排除理由 |
| 观察窗口 | 单笔记排序与展开状态、连续观察起止、首尾位置、主评论/回复覆盖、滚动或断层、未显示范围、可见/排除/合格计数 |
| C评论 | N关联、必要短原文或明确概述、获取时点、相对位置和回复关系、父评论语境、可见互动、定位方式/E、脱敏和排除原因 |
| DUP去重 | 技术重复/同文复制/疑似模板/同义不同来源/待核、关联记录、保留主记录、计数处理、判断依据和限制 |
| P问题 | C/N或个人素材关联、显性问题、推测需求、支持和反方、样本限制、最低成本验证 |
| T候选去向 | 关联P、五门槛与研究层级（适用时）、保留/修改/排除理由、缺口及负责人、对应正式内容位置或Content ID（已有时） |
| 专业与平台核验 | 具体拟表达事实、直接可靠来源、发布/更新/查看日期、适用对象和账号范围、来源差异、审核人资格与结论、剩余未知 |
| 人工审核反馈 | 具体版本、业务/专业/最终选择分别的人员日期、通过范围、修改或退回原因、实际使用反馈 |
| 数量与效率 | 分别列O、D、U、L、V、G、候选、正式推荐、明确认可九项及V/D；批内去重、新增和累计分列，不相加重复CID；B1耗时单列，B2/B3实际耗时、剩余额度及停止原因可查 |
| 失败与偏差 | 访问/证据/价值或合规类别、发生环节、可见现象、已尝试合法动作、停止原因、替代路线及授权；热门、排序、自选择、登录个性化、集中度、不可见/隐私排除偏差 |
| E证据存储 | 支持哪项结论、观察时间、对象与范围、可复核方式、来源和权限、必要保留期限、状态；未取得的资料明确未读 |

### 受控证据与公开报告分开

可回查个人的笔记/评论链接、可搜索定位的健康原话、原始截图和敏感上下文仅能在已授权受控位置保留必要部分。公开仓库不保存这些材料、受控访问链接或本机绝对路径；只留无法反查个体的概述和非敏感索引。不得以删昵称就宣称匿名化。官方规则与专业书目等公开非个人来源可按许可登记。

敏感资料不能安全脱敏就排除，不以“内部证据区”名义放进公开仓库；提交空模板并不授权保存未来填入的敏感证据。跨环境转交前核必要性和访问范围；保留期限由实际用途与授权确定，V2的30日检查是候选管理建议，不在本次自动设成政策或删除任务。

### 返回 Chat 的结论

已完成____；未完成____；最值得共创的题目及理由____；不建议方向及理由____；可查证据索引____；需要澜心决定的一件事____；下一步获授权后可做____。复核者逐项检查正文与证据对应，确认缺口是否阻止推进。

同时交付五项：A中文三层报告；B经筛选的原创视频候选；C每题完整推荐理由；D已确认事实与待核内容清单；E可直接进入Chat共创的摘要。Excel是证据后台，不能代替A—E。

每个候选使用以下短卡，随后附完整自然语言论证；没有合格题目可以交0题及排除原因：

| 候选卡字段 | 填写要求 |
|---|---|
| 工作标题 | TID、版本、候选/推荐/暂缓/排除及对应PID |
| 用户具体场景 | 实际来源支持的人群与情境；年龄、病情未知不推定 |
| 核心问题 | 一题主要回答什么 |
| 评论与研究证据 | 受控CID/NID/EID索引、安全概述、支持范围及反例 |
| 与澜心IP的联系 | 已确认Brain条目，不能只写“符合定位” |
| 澜心可提供的独特解释 | 有依据的经验或知识、必要专业审核；不得编造资质 |
| 一个核心观点 | 标明AI候选或已确认观点；不冒充澜心原话 |
| 内容价值 | 观众能理解或决定什么，未验证价值要明示 |
| 原创表达形式 | 形式及选择理由；不用他人素材和结构冒充原创 |
| 主要专业边界 | 五门槛逐项、适用证据、禁承诺及停止条件 |
| 当前制作条件 | 人员、素材、授权、专业审核与三平台缺口 |
| 推荐或暂缓原因 | 取舍、替代解释、推翻条件和一个最必要的确认 |

Chat收到后核对来源、版本、五门槛与权限，只把公开安全摘要衔接现有Content主记录；已有Content则引用原ID，不因研究来源另建库。研究认可不自动写完整脚本、扩量或发布；澜心明确要求文案/脚本时可直接利用已确认资料共创，不重走研究。

### 统计与能力回执

按研究参考的九项定义填数。未执行写“未执行”；已执行且D=0写V/D“不适用”；U始终披露。无有效问题的可安全判重评论仍保留在D，一条评论多个问题时V只计一次。V/D仅描述本轮已判定子样本，不是女性用户占比、患病率、需求规模或转化率；问题支持数和不同笔记数不是独立用户数。对未定位、待判重、隐私排除和样本集中度解释其影响。

执行回执分列：已建立规则、已配置工具、已验证访问能力、已完成真实研究，各项注明实际证据或“未验证”。本轮运行状态按研究参考七状态填写；“研究完成”需相应交付与复核，不能由有数据或有候选自动触发。

## 交付检查

每条重要推荐能从中文正文看懂“依据—解释—限制—取舍”，并能沿索引回查；所有未知、推测和替代角度有标记；五门槛与平台意见相容；原话不被改写冒充；零候选允许；未做的浏览、专业审核、拍摄、发布和效果验证没有被报告为完成。澜心是否看懂须来自实际反馈，不能由 AI 自评写成已通过用户验收。
